# devkit v1.2.0: Flow records what really happened

Date: 2026-10-31

## Summary

When a maintainer runs the flow commands, the GitHub records (releases,
close reasons, and versions) match what really shipped, with no manual fix.

## Upgrade

- The review jobs now limit `Read`, `Grep`, and `Glob` to the checkout and
  the PR context folder. Do not add a bare `Read`, `Grep`, or `Glob` with
  `extra_allowed_tools`.
- `/flow:release-milestone` now publishes the GitHub release and marks it
  Latest when `.claude/project.md` has no `release` key. Before, it always
  made a draft. A project that publishes the release at deploy time must
  add `` release: `draft` `` to keep the old behavior.
- When `main` requires linear history (classic branch protection or a
  ruleset), `/flow:release-milestone` now squash-merges the milestone PR.
  `main` gets one commit for each release. If `main` does not require it, the
  command makes a merge commit, as before.
- Before it changes anything, `/flow:release-milestone` now reads the branch
  protection of `main`. This read needs admin read access to the repo. If the
  person who runs the release does not have it, the script stops with exit 1
  and changes nothing.
- `/flow:plan-milestone` and `/flow:start-milestone` now stop on a bad
  version before they change anything. `flow-check-version-newer` now
  needs a leading `v` on the candidate (`v1.2.0`, not `1.2.0`).
- A culled issue now closes as `not planned` or `duplicate` and leaves its
  milestone. `/flow:finish-issue` closes an issue as `completed`. The
  duplicate close needs a `gh` version that has `gh issue close
  --duplicate-of`.
- `/flow:setup` now also creates the `deep-review` label.
  `/flow:review-milestone` adds this label to start a recovery review. In
  a project that ran `/flow:setup` before, run `flow-labels --missing` and
  then `flow-labels --create`, or run `/flow:setup` again.
- `flow-labels` no longer reports an existing label as missing when the
  repo has many labels. A pipe into `grep -q` failed with EPIPE, mostly on
  macOS.
- For each test proof, `flow:senior-test-engineer` now makes and removes a
  `git worktree` in the scratchpad. A hook or sandbox that blocks
  `git worktree` makes the agent report the check as not checked.

## Verification

- Check out the `v1.2.0` tag. Run `bash tests/run.sh`. All tests must pass.
- Run the lint set: markdownlint, yamllint, actionlint, and shellcheck. CI
  runs the tests and the lint on `ubuntu-24.04` and `macos-15`.
- In a project that uses devkit, run `/flow:start-milestone` with a version
  that has no leading `v`, for example `1.2.0`. The command must reject it.
- In the same project, remove the `release` key from `.claude/project.md`.
  Run `/flow:release-milestone`. The command must publish the release and
  not make a draft.
