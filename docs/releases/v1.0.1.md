# devkit v1.0.1: Review gate you can trust

Date: 2026-10-30

## Summary

A green review check now means that a Claude review ran and that only
trusted comments steered it. This release closes two security gaps in the
Claude workflows and makes the Gate name the cause when no review ran.

## Issues Resolved

- [#29](https://github.com/unibrain1/devkit/issues/29) — security:
  check whether review allowedTools git prefixes allow --output file writes.
  `claude-review.yml` and `claude.yml` no longer allow `git log`, `git show`,
  or `git diff`.
- [#30](https://github.com/unibrain1/devkit/issues/30) — security:
  review prompts give rebuttal weight to PR comments from any GitHub user.
  The reviewer now reads only owner, member, collaborator, and
  `github-actions` comments.
- [#31](https://github.com/unibrain1/devkit/issues/31) — fix: review
  gate guard and failure messages give the wrong cause in some cases.
  When no review ran for an unexpected cause, the PR gets a "did not run"
  note, and the Gate fails.
- [#32](https://github.com/unibrain1/devkit/issues/32) — fix: review
  gate passes when no review ran on a branch cut from a tag.
  The Gate fails on a stale workflow copy and tells you to sync it.

## Upgrade

- A caller that pins a tag in `uses:` must change the ref to the v1.0.1
  tag. A caller on `@main` needs no change.
- Remove each git rule from `extra_allowed_tools` in both workflows, for
  example `Bash(git log:*)`.
- For `claude-review.yml` only, also remove each tool that reads PR
  comments, for example `Bash(gh pr view:*)`. `claude.yml` keeps it.
- After you change the caller on the default branch, merge the default
  branch into each open milestone branch. Until then, a PR into that branch
  runs the old workflow (tag pin), or fails the Gate as stale (`@main`
  pin). A branch cut from a release tag has the same old copy.
