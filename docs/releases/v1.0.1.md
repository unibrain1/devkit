# devkit v1.0.1: Review gate you can trust

Date: 2026-10-29 (draft)

## Summary

A green review check means that a Claude review ran and that only trusted
comments steered it. This release closes two security gaps in the review
prompts and makes the Gate fail with the correct cause when no review ran.

## Issues Resolved

- [#29](https://github.com/unibrain1/devkit/issues/29) — security:
  check whether review allowedTools git prefixes allow --output file writes.
  The Claude workflows no longer allow `git log`, `git show`, or `git diff`,
  so Claude cannot use `git --output` to write a file.
- [#30](https://github.com/unibrain1/devkit/issues/30) — security:
  review prompts give rebuttal weight to PR comments from any GitHub user.
  A workflow step now gives the reviewer only owner, member, and
  collaborator comments and `github-actions` comments
  ([#39](https://github.com/unibrain1/devkit/issues/39)), with a count of
  the others. By default, the review jobs give the reviewer no tool that
  reads PR comments ([#40](https://github.com/unibrain1/devkit/issues/40)).
- [#31](https://github.com/unibrain1/devkit/issues/31) — fix: review
  gate guard and failure messages give the wrong cause in some cases.
  When the review action stops early, the PR gets a note and the Gate names the cause.
- [#32](https://github.com/unibrain1/devkit/issues/32) — fix: review
  gate passes when no review ran on a branch cut from a tag.
  The Gate fails on a stale workflow copy and tells you to sync it.
