# v1.4.0 — Repo families

Date: 2026-11-10 (draft)

## Summary

A maintainer can start a new repo from a family template through a
requirement-driven setup. A maintainer can also move an existing repo to its
family template, so that repos in one family differ only in content and
deploy target.

## Issues Resolved

- [#113](https://github.com/unibrain1/devkit/issues/113) — feat: every-repo baseline for checks that do not depend on the stack. `/flow:setup` adds the missing baseline files: pre-commit hooks, Claude and secrets-scan callers, and Dependabot.
- [#118](https://github.com/unibrain1/devkit/issues/118) — feat: Family A templates for static sites (Cloudflare and host). `node-site.yml` gets an optional `lint_script` input for the host CSS and PHP lint.
- [#115](https://github.com/unibrain1/devkit/issues/115) — feat: Family W template for web apps. One stack-neutral template with command placeholders, two host texts, and an `.env` block hook.
- [#114](https://github.com/unibrain1/devkit/issues/114) — feat: Family B template and a reusable container-image workflow. A hotfix now gets a patch tag, so `latest` moves.
- [#116](https://github.com/unibrain1/devkit/issues/116) — feat: Family I template for iOS apps. SwiftLint runs at commit and `xcodebuild test` at push, with no macOS CI.
- [#117](https://github.com/unibrain1/devkit/issues/117) — feat: /flow:new-project creates a repo from a family template. It asks the setup questions, recommends a family, and fills the template with `flow-template`.
- [#92](https://github.com/unibrain1/devkit/issues/92) — feat: /flow:setup installs or checks the enabled plugins. `flow-plugins` finds a missing or old plugin, and the session start reports it.

## Deployment instructions

TBD. Each issue adds its steps here.

- #113: in each repo, run `/flow:setup`, then do the manual steps in [docs/baseline.md](../baseline.md): `pre-commit install`, the Semgrep and GitGuardian apps, and push protection in a public repo.
- #118: no step for an existing repo. The templates are for `/flow:new-project` (#117). A static site moves to its template in phase 3.
- #115: no step for an existing repo. MyGunLog moves to the template in phase 3, and Registry at a Registry milestone boundary.
- #114: before a container repo moves to `container-image.yml`, change its host pull tag to `latest` or a version (Monitoring: `:main` to `:latest`). See [ci-workflows.md](../ci-workflows.md#host-pull-tag).
- #114: `flow:hotfix` now runs `flow-release-hotfix`, which makes the hotfix tag `vX.Y.(Z+1)`. At the next devkit pin bump, Registry and Registry2 remove the four-part tag step from `docs/development/DEPLOYMENT.md`. If an open milestone has the next patch version, the script stops. Change the milestone version first.
- #116: no step for an existing repo. DryFireTimer moves to the `ios-app` template in phase 3.
- #92: in each repo, run `/flow:setup --check`. If it reports a missing or old plugin, run `/flow:setup` to install or update it, then `/reload-plugins`.
- #117: no step for an existing repo. Start each new repo with `/flow:new-project` in an empty folder.
- #116, #117: the `ios-app` allow rule is now the exact test command, not `Bash(xcodebuild test:*)`.
